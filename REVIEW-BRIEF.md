# Daily Crit lesson review brief

Claude puts this at the top of every `lessons-review.md` so the file can be pasted straight into another AI for a second opinion.

---

You're reviewing lessons for Daily Crit (dailycrit.app), a site that teaches UI design principles with short interactive lessons. Each lesson shows a flawed phone screen with a "problem" tooltip, then the screen animates into a fixed version with a "fix" tooltip.

**How the lessons work (please don't flag these as problems):**
- Each lesson teaches **one primary principle**. Related principles are listed as tags, so the tooltips don't need to explain every concept involved.
- Tooltip titles are under about 8 words. Tooltip bodies are one or two sentences, about 35 words max. Every word counts, so caveats come at the cost of the main point.
- The visitor also **sees** the before and after screens. The tooltip doesn't have to describe everything that changes.
- Lessons can use made-up research if it's clearly framed as an example ("In this example, interviews showed…"). Flag research only if it reads like a real study.
- Simplifying is fine. A rule of thumb like "about 1.5 line height" doesn't need every exception spelled out.

**What to look for, in this order:**
1. **Wrong:** anything a designer would get wrong if they repeated it in a design review.
2. **Misleading:** a claim that only holds in some cases but reads as always true, *in a way that matters for this lesson*.
3. **Unclear:** wording a designer early in their career would stumble on.

**What to skip:**
- Caveats or side issues that would pull focus from the primary principle.
- Asking for the tooltip to mention secondary changes that are visible on the screen anyway.
- Style preferences, unless the text is actually hard to follow.

**How to write your feedback:**
- At most 3 points per lesson. If a lesson is fine, say "No changes needed."
- Tag each point **Must fix**, **Consider** or **Optional**.
- Describe the problem and why it matters, not rigid instructions like "clarify that…" or "acknowledge…". If you suggest new wording, keep it within the length limits above.
- Say what's working, so it doesn't get changed by accident.
